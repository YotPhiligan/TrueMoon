# TALES-20261121-7774189b — Открытие игрового проекта в Editor при отладочном запуске EXE

- Дата UTC: 2026-11-21.
- Потребитель: TrueMoon.Tales.Game `1.2611.21.5-alpha`.
- Модуль: engine. Capability: `engine.single-game-debug-editor-launch`.
- Пакеты потребителя: TrueMoon.Aether.Player, Runtime и Tooling `1.2611.21.10-alpha`.
- Связанный контур: [ENG7b.3, запуск Editor, Player и RuntimeChild](../../../engine/LAUNCH_ACCEPTANCE.md).

## Сценарий

Пользователь запускает игровой EXE в отладочном профиле, например через F5
в IDE. Для приложения, у которого явно задан один игровой проект и один
основной EXE, открывается Aether Editor с уже открытым проектом этой игры.
Редактор стартует в режиме редактирования. Игровая сессия создаётся по
команде Play. Обычный запуск поставки игры ведёт в Player.

Пример потребителя — TrueMoon.Tales. Сейчас его [точка входа](../../../../../../TrueMoon.Tales.Game/src/TrueMoon.Tales/Program.cs)
задаёт роль Player и принимает артефакт сборки со сценой. Сборщик игры
публикует готовую сцену и игровой артефакт. Для отладочного профиля нужно
определить привязку к редактируемому проекту `.aetherproj` и его исходникам.

## Что уже есть

[Общий разбор параметров](../../../../TrueMoon.Aether.Runtime/Hosting/AetherLaunchOptions.cs)
выбирает Editor, Player или защищённую внутреннюю роль RuntimeChild до
построения App. Роль по умолчанию задаёт вызывающий host. Editor принимает
`--project`, Player требует `--artifact` и `--scene`. В [примере AetherHost](../../../../Examples/AetherHost/Program.cs)
уже есть комбинированная точка входа. Приёмка ENG7b.3 покрывает отдельные
и комбинированные host, включая штатный Play/Stop. Связь отладочного запуска
конкретного игрового EXE с единственным проектом потребителя отдельно
предстоит принять. Заявка на поведение запуска, статус proposed.

## Предлагаемый первый срез

- Сделать явный отладочный профиль для приложений с одной игрой. В профиле
  указать, какой игровой EXE запускается и какой `.aetherproj` ему
  соответствует. Разрешение пути привязано к заданному корню проекта или
  метаданным запуска и даёт тот же результат при смене рабочего каталога.
- Подключить выбор к существующему маршруту Aether. Сохранить приоритет
  защищённого запуска RuntimeChild и проверку его идентичности. Явный
  допустимый выбор роли имеет приоритет над пользовательским значением
  профиля по умолчанию. Для отсутствующего или неоднозначного проекта
  показать причину отказа от отладочного запуска.
- Открыть один Editor с указанным проектом и проверить штатный Play/Stop.
  Использовать текущие правила владения окном и runtime-процессом, проверки
  идентичности артефакта и сохранения правок проекта.

## Ограничения, которые нужно определить

- Как распознавать отладочный запуск. Согласовать поведение F5 из IDE,
  ручного запуска Debug EXE и подключения отладчика к работающему Player.
  Рабочий вариант для первого среза — явный профиль разработки с режимом
  по умолчанию для этого игрового проекта.
- Что требуется для редактирования и Play. Определить источник
  `.aetherproj`, доступность исходников и нужных ресурсов, проверку
  актуальности артефакта и момент вызова Build. Пакет Player с замороженным
  артефактом и рабочая копия с проектом имеют разные входные данные.
- К какому процессу подключается отладчик при Play. Зафиксировать,
  отлаживается ли код игры в дочернем Runtime, как к нему подключаться
  и что происходит с точками останова при Stop и следующем Play.
  Горячая замена кода требует отдельной проверки.
- Где поставляются зависимости Editor/Tooling и SDK для разработки.
  Определить поддерживаемую конфигурацию Debug-поставки. Player-only
  Release сохраняет свой граф пакетов и запуск.
- Как вести себя, если этот проект уже открыт или пользователь пытается
  сменить его в Editor. Согласовать повторное использование окна,
  сохранение несохранённых изменений и границу Play для чужой игры
  из host, привязанного к одному EXE.

## Приёмка

1. В Windows x64 из отладочного профиля TrueMoon.Tales запустить игровой
   EXE и увидеть Editor с нужным `.aetherproj` в режиме редактирования.
   Повторить из другого рабочего каталога.
2. Из Editor выполнить Play → Stop → Play. Оба запуска используют артефакт
   выбранной игры. После Stop Editor и открытый проект доступны для правок.
3. Проверить явный запуск Player и обычный запуск Release. Подтвердить
   прежний вход Player-only и отсутствие Editor/Tooling в его графе.
4. Проверить отсутствующий проект, неподходящий артефакт и некорректный
   защищённый bootstrap. В каждом случае диагностика объясняет причину,
   а выбор роли остаётся предсказуемым.
5. Для повторного запуска и отладки игрового кода описать фактически
   поддержанные действия, требования к установке и известные ограничения.

Сценарий сверили по текущим исходникам и прежней приёмке ENG7b.3.
Новый отладочный профиль ожидает реализации и отдельной проверки.
Контракт профиля и состав первого среза согласует владелец Aether.
