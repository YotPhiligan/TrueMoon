# ARCH1g.2 — импортированная модель в Build, Runtime и Player

Authoring App подключает `UseNom()`, `UseAetherModelImport()` и
`UseAetherNomContent()`. Мост `TrueMoon.Aether.Nom` принимает опубликованный
`PublishedModelImport` из [ledger](MODEL_SUBASSET_LEDGER.md) и заимствует открытый
проектный store на время вызова. Создание App и регистрация моста обходятся без
открытия store, запуска importer и компиляции.

```csharp
var snapshot = await bridge.PublishAsync(store, publishedModel, store.ContentGeneration, token);
var renderContent = await bridge.CaptureAsync(store, snapshot.Id, token);
var result = await compiler.BuildAsync(request with { RenderContent = renderContent }, token);
// In Runtime, after opening the selected artifact through GameBuildLoader:
using var content = catalogFactory.Create(loader.Artifact.RenderContent!);
```

`PublishAsync` отправляет целый набор mesh/material/binding-set ресурсов одним
Nom batch с ожидаемой generation. Ledger даёт постоянные AssetId, SlotId и
семантические locators. Canonical RenderContentCodec даёт байты и SHA256 каждой
ревизии. Binding set указывает точные ключи своего меша и материала. Все
ресурсы этой модели входят в roots снимка с exact versions из receipt, поэтому
захват не читает текущие heads по AssetId.

Nom сначала фиксирует ресурсы, затем создаёт снимок. Если вторая
операция завершится ошибкой, принятый commit Nom сохранится. Повторная публикация
проверяет текущую generation. Удержание снимка и закрытие store принадлежат caller.
Capture открывает lease и потоки внутри одного вызова, проверяет kind, длину,
digest и связи ресурсов, затем возвращает собственную копию байтов. Пределы
первого профиля — 256 roots и 12 MiB итогового payload. Удаление Nom heads при
удалении ресурсов из модели остаётся отдельной операцией.

Build копирует payload в тот же staging, что и игровую DLL. Schema 3 добавляет
фиксированный файл `render-content.bin` с проверяемыми длиной и SHA256. Его
SHA входит в `game-build.json`, а SHA манифеста задаёт BuildId. Публикация
использует существующий перенос целой staging-директории. Запрос без
`RenderContent` сохраняет schema 2 и форму манифеста. Managed compiler reuse
может повторно использовать DLL, а publish всегда берёт render input текущего
запроса.

Runtime открывает артефакт по точному BuildId, проверяет весь payload до
загрузки игровой сборки и включает файл в pin артефакта. Он восстанавливает
`RenderContentManifest` со своим BuildId. Runtime consumer явно получает
CPU lease через `UseAetherRenderResources()` и
`IFactory<RenderManifestLease, RenderContentManifest>`. Пакет Runtime может
читать артефакт самостоятельно. Nom, Tooling и Assimp нужны на стороне
authoring.

[Воспроизводимый прогон](../../ManualTests/ModelBuildConsumer/README.md) выполняет
два реальных импорта статического glTF с разной координатой вершины. Он
сверяет постоянные ID, точные старую и новую ревизии и совпадение байтов
игровой DLL. После второго импорта исходный снимок Nom снова строит прежний
BuildId. Отдельные Runtime-процессы получают обе версии из артефактов после
закрытия и перемещения Nom и исходников. Изменённая копия payload отклоняется.
[Фактические результаты](HISTORY.md#arch1g2a-2026-11-18)

<a id="arch1g2b-scene-gpu"></a>
## ARCH1g.2b — размещение и GPU

`ImportedModelScene.Place(scene, publishedModel, placement)` в Tooling возвращает
новую ревизию сцены. Постоянный ID экземпляра из ledger становится EntityId.
Экземпляры одного mesh используют общее определение с MeshRenderer, который хранит
стабильные mesh и binding-set AssetId. Поза узла из импорта компонуется с placement
и записывается в Transform v1. Этот формат поддерживает положительный масштаб,
поворот и перенос. Сдвиговая деформация (shear) и отражение отклоняются. Повторное
размещение одного импорта в той же сцене требует отдельной схемы ID размещения.
Caller сохраняет документ через существующий codec `.aetherscene`.

Игра с `RuntimeAccess` может реализовать `IGameBuildSessionEntry`. Штатная фабрика
Runtime передаёт ей проверенный `RenderContentManifest` выбранного артефакта на
время жизни сессии. Фабрика игры связывает `MeshRenderingComponents` с этим
манифестом, а `SceneWorldLoader` разрешает ссылки ECS при загрузке сцены.
Вход без render payload отклоняется при активации такого entry. Для
`IGameSessionEntry` и явно зарегистрированной пользовательской фабрики
действует прежний контракт.

Проверка использует одну сцену с камерой и двумя экземплярами одного
импортированного меша. Player получает её через `PlayerStart.CaptureAsync`.
Три последовательных запуска проверяют старый BuildId, новый BuildId и снова
старый BuildId. Проверка сверяет штамп сцены и манифеста, затем считывает пиксели
после представления Vulkan-кадра на Skia OpenGL surface. Замена одной вершины
увеличивает площадь изображения обеих копий, старый билд при повторном открытии
даёт идентичную маску. [Фактические результаты](HISTORY.md#arch1g2b-2026-11-18)

<a id="arch1g2c-editor-builds"></a>
## ARCH1g.2c — выбор опубликованного артефакта в Editor

`EditorScenePlayback.RunSelectedBuild(artifact)` передаёт полный документ
открытой сцены как `SceneWorldData`. Обычный допуск команд Editor фиксирует
активный проект и ревизию документа. Render content при наличии должен
принадлежать этому проекту. `GameEditor.SelectBuildForContextAsync` проверяет
артефакт и связывает кандидат с точной версией контекста. Startup ждёт
фактического GPU-present текущей поверхности перед переходом в Playing.
Команда использует опубликованный артефакт, поэтому ей достаточно его
runtime-совместимого BuildId и файлов. Проект и сцена остаются у Editor,
дочерняя игра владеет своей копией World.

Прямой запуск выбранной сборки доступен между `Stop` и следующим запуском.
`Stop` освобождает дочернюю сессию и её viewport. Устаревшее выделение сборки
и изменение контекста сохраняют прежние fences запуска.

<a id="arch1g2d-world-replace"></a>
## ARCH1g.2d — горячий Replace полной сцены

`EditorScenePlayback.ReplaceSelectedBuild(artifact, token)` меняет сборку
у принадлежащей Editor игры на той же открытой ревизии сцены. Runtime
сверяет точные данные сцены с активным запуском, включая digest при повторном
чтении документа. Игра поддерживает `ICheckpointGameSession` и отвечает за
совместимость игрового состояния. При замене новая игра загружает полный
документ, применяет checkpoint на Paused, представляет первый кадр и
возвращается к прежнему режиму. Полный World и игровые ресурсы принадлежат
своему дочернему процессу. Транзакция подтверждает первый mesh-кадр после
представления в том же окне Editor.

Повреждение артефакта при проверке выбора отклоняет его до остановки старого
child. Отмена после освобождения прежнего child прерывает кандидата и запускает
одну попытку вернуть прежнюю сборку, документ, checkpoint и режим. Явный
`Stop` или закрытие Editor прерывают восстановление и дожидаются освобождения.
Проверка сохраняет GPU-кадры до и после обеих ветвей отказа.

<a id="arch1g2e-editor-build-picker"></a>
## ARCH1g.2e — выбор сборки из меню Editor

В меню **Проект → Выбрать опубликованную сборку** введите полный `BuildId`
из настроенного каталога сборок или абсолютный путь к папке артефакта.
Для остановленной сцены действие запускает выбранную сборку. Во время
работы полной сцены из опубликованного артефакта действие выполняет Replace.
Редактор показывает короткий ID фактически работающей сборки в заголовке.
Полный ID входит в доступное описание заголовка.

Открытое поле фиксирует проект, ревизию документа и целевую сессию. При их
смене нужно заново открыть выбор. Чтение и проверка артефакта проходят в
существующей фоновой операции. После отмены с успешным откатом интерфейс
сообщает о восстановлении и показывает восстановленный BuildId.

<a id="arch1g2g-model-revisions"></a>
## ARCH1g.2g — зависимость, настройка и удаление модели

Один glTF проходит три публикации. Изменение внешнего BIN меняет
InputRevision при тех же байтах корневого файла. `GeometryScale` создаёт
новую ревизию CPU-кандидата на тех же захваченных байтах. Настройка
применяется к локальной геометрии и сохраняется в ledger, а позы и
постоянные ID остаются в той же сцене. В проверенном случае обе правки
меняют канонический render payload и BuildId. BuildId адресует содержимое
артефакта, поэтому одинаковый render payload допускает повторное
использование сборки при одинаковых остальных входах.

После `DeleteResourcesAsync` текущих heads нет. Сохранённые точные снимки
Nom продолжают давать те же BuildId. После удаления снимков, очистки
журнала публикаций и сборки мусора Player открывает все три уже
опубликованных артефакта из их собственных render payload.
[Проверки](HISTORY.md#arch1g2g-2026-11-18).

<a id="arch1g2h-multiple-models"></a>
## ARCH1g.2h — несколько моделей в одной сборке

`NomModelContent.CaptureSnapshotsAsync(store, snapshotIds, token)` принимает
от 1 до 32 точных ID из одного Nom store. У каждого снимка до 256 членов,
у объединённого результата до 1024 уникальных записей и до 12 MiB в
закодированном payload. Снимки публикуются и удерживаются вызывающим кодом.
Во время захвата мост читает по одному lease и освобождает его при любом
исходе. Если снимок исчез, захват завершается ошибкой.

Одинаковый AssetId с тем же kind и digest канонических байтов входит в
результат один раз. Разные ревизии того же AssetId отклоняются до передачи
данных компилятору. Порядок и повтор ID снимка не влияют на BuildId.
Готовый артефакт открывается через прежний Runtime/Player и содержит байты
всех выбранных моделей.

<a id="arch1g2i-import-freshness"></a>
## ARCH1g.2i — актуальность импорта перед сборкой

На стороне authoring сопоставьте каждый выбранный снимок с опубликовавшим его
`PublishedModelImport`. Создайте для модели новый `ModelSourceCapture` через
фабрику `UseAetherModelSourceCapture()` и вызовите
`CheckFreshnessAsync(published, geometryScale, token)` перед захватом ресурсов
для новой сборки. Метод использует штатный ограниченный захват корневого файла
и его зависимостей. Он сравнивает полученный `InputRevision` и запрошенный
`GeometryScale` с опубликованным импортом.

- `Current` разрешает использовать выбранный снимок.
- `Stale` указывает на изменение входных байтов, настройки или обоих. Для новой
  сборки с актуальными входами вызовите штатный импорт и опубликуйте новый снимок.
- `Unavailable` содержит ошибку захвата. `InputChanged` в этом случае неизвестен.

Отмена прерывает проверку. Ошибки аргументов возвращаются как исключения.
Проверка одноразовая и освобождает файловые handles до возврата результата.
Она читает источники без worker и записей в ledger или Nom. Результат описывает
байты на момент захвата. Компилятор и Player работают с выбранными замороженными
артефактами, а решение допустить новую сборку принимает authoring.

[Воспроизводимый профиль](../../ManualTests/ModelBuildConsumer/README.md#two-models-in-one-build).

<a id="arch1g2j-model-source-watch"></a>
## ARCH1g.2j — уведомления об изменении модели

`UseAetherModelSourceCapture()` регистрирует
`IFactory<ModelSourceWatch, ModelSourceWatchArguments>`. Authoring создаёт
watch для конкретного исходника, опубликованного импорта и масштаба. При
смене выбора закрывает этот watch и создаёт новый. `Read()` возвращает
последнюю завершённую проверку без I/O, либо `null` до первой проверки.

После первого успешного захвата watch подключает уведомления для каталога
модели и повторяет проверку. События для корня, известных зависимостей и их
родительских каталогов объединяются в один сигнал. После сигнала выполняется
тот же полный захват и сравнение байтов, что в g.2i. Список зависимостей
уточняется после каждого успешного захвата. При ошибке захвата сохраняется
последний известный список, поэтому появление удалённого BIN может разбудить
проверку. Периодический полный опрос работает и при недоступных уведомлениях.

В одном App допускается до восьми активных watch. Интервал полного опроса
настраивается от 100 мс до минуты, по умолчанию 10 с. На каждую проверку
выделяется до 5 с кооперативного захвата. `DisposeAsync` и остановка App
дожидаются завершения захвата и освобождения файлового наблюдателя.
Для допуска новой сборки authoring по-прежнему вызывает явную проверку g.2i.

<a id="arch1g2k-editor-model-imports"></a>
## ARCH1g.2k — актуальность выбранных моделей в Editor

Зарегистрируйте `UseAetherModelSourceCapture()` до `UseAetherEditor()` или
`UseConfiguredAetherEditor()`. Authoring-композиция передаёт в
`SceneDocumentSession.SelectModelImportsAsync` `OpeningId` открытого документа,
имена и точные опубликованные поколения моделей с параметрами исходников,
а также `GameBuildRenderContent` из выбранных ревизий. Сессия проверяет ключи
геометрии, материалов и привязок, включая их ревизии и принадлежность проекту.

Строка состояния Editor открывает панель со статусом каждой выбранной модели.
Сессия владеет наблюдателями и дожидается их остановки при смене выбора или
закрытии документа. Выбор действует в текущем открытии сцены. Его задаёт код
authoring-композиции, который после реимпорта может выбрать новое поколение.

Штатные Build, Start и Replace из документа повторяют проверку g.2i. При
устаревшем или недоступном импорте Editor называет модель и останавливает
операцию до запуска компилятора. При успехе запрос сборки получает полную сцену
и ранее выбранный замороженный payload. Выбор опубликованной сборки работает
с её артефактом и не требует захвата исходников.

[Воспроизводимый профиль](../../ManualTests/ModelBuildConsumer/README.md#selected-model-imports-in-editor).

<a id="arch1g2l-editor-reimport"></a>
## ARCH1g.2l — реимпорт выбранной модели из Editor

Зарегистрируйте `UseAetherModelSourceCapture()` и `UseAetherModelImport()` до
Editor. Для Nom подключите `UseNom()` и `UseAetherNomContent()`. Фабрика
`IFactory<IModelImportContentPublisher, IProjectAssetStore>` принимает открытое
хранилище проекта и возвращает заимствующий его publisher. Владелец проекта
удерживает хранилище открытым до завершения работы документа и управляет
хранением долговечных снимков Nom.

Для нужной `SceneModelImportSelection` задайте `Reimport` через
`SceneModelReimportSettings`. Настройки содержат ledger того же `SourceId`,
проверенный worker, каталог scratch и publisher проекта. В панели состояния
Editor появится действие «Переимпортировать» с именем модели. Действие использует
точную привязку к открытию документа, источнику и выбранному поколению.

Tooling захватывает исходники, запускает worker и перед записью сверяет
постоянные ID, состав, размещение и привязки модели с используемой сценой.
Ledger публикуется с ожидаемым поколением. Publisher Nom публикует ресурсы
и захватывает точный снимок. Документ подменяет только замороженные ресурсы
и наблюдатель этой модели. Build заново проверяет исходники по g.2k.

Отмена и ошибка до смены выбора сохраняют выбранный набор для сцены. Если ledger
успел сохраниться, повтор может взять ровно следующее поколение с теми же
захваченными входами и масштабом. При другом поколении или другой ревизии
источника Editor просит заново выбрать импорт. Опубликованные ledger и Nom
сохраняют свои границы атомарности. Предыдущие сборки хранят собственные ресурсы.

[Воспроизводимый профиль](../../ManualTests/ModelBuildConsumer/README.md#reimport-a-selected-model-in-editor).

<a id="arch1g2m-persisted-model-selection"></a>
## ARCH1g.2m — сохранённый выбор импортов сцены

Зарегистрируйте `UseAetherSceneModelSelectionPersistence()` до подключения
Editor вместе с `UseAetherModelSourceCapture()`. Явный выбор импортов и успешный
реимпорт сохраняют отдельную запись `.aether-model-imports/<SceneId>.tmimports`
в каталоге контента проекта.
Она принадлежит проекту и идентичности сцены. `Save As` с тем же `SceneId`
использует тот же выбор. Запись хранит точные опубликованные поколения и
относительные пути внутри проекта. Формат `.aetherscene` сохраняется.

Editor читает выбор до смены документа и восстанавливает замороженный набор
из сохранённых поколений. Открытие читает запись даже тогда, когда основной
ledger уже указывает на более новое поколение. После открытия наблюдатели
обновляют статусы. Перед Build по-прежнему выполняется проверка g.2k.

Запись меняется атомарно относительно отпечатка, прочитанного при открытии
или последней успешной смене выбора. Конфликт сохраняет текущий выбор и
запись другого автора. Невалидная запись останавливает открытие до замены
документа. Переимпорт может успеть опубликовать ledger и ресурсы Nom до отказа
записи выбора. Границы публикации остаются раздельными, как в g.2l.

Приложение может зарегистрировать
`IFactory<SceneModelReimportSettings, SceneModelReimportRestoreArguments>`.
Фабрика получает проект и восстановленную ссылку на ledger. Она выдаёт
настройки из доверенной конфигурации и заимствует publisher проекта. Worker,
scratch и настройки запуска задаются приложением. Сохранённый выбор поддерживает
статусы и Build и при отсутствии этой фабрики.

[Воспроизводимый профиль](../../ManualTests/ModelBuildConsumer/README.md#restore-the-saved-model-selection).

<a id="arch1g2n-project-model-catalog"></a>
## ARCH1g.2n — модели проекта в Editor

Подключите `UseAetherProjectModelCatalog()` вместе с `UseAetherModelImport()`,
`UseAetherModelSourceCapture()` и `UseAetherSceneModelSelectionPersistence()`
до Editor. В стандартном примере `Examples/AetherEditor` этот набор включён.
После публикации импорта authoring-пайплайн получает `ProjectModelCatalog`
из `IFactory<ProjectModelCatalog, ResolvedProject>` и вызывает
`RegisterAsync` с именем, параметрами исходника и ссылкой на ledger.
Записи сохраняются в `.aether-model-catalog.json` в каталоге контента проекта.
У существующего импорта регистрацию можно выполнить по его опубликованному ledger.

Откройте сведения Editor через строку состояния и нажмите «Модели проекта».
Список показывает имена и пути зарегистрированных моделей. Флажки выбирают
ресурсы для текущего открытия сцены. При первом выборе берётся опубликованное
поколение из ledger. Прежние выборы сохраняют привязанные поколения, а повторное
открытие сцены восстанавливает её отметки из записи ARCH1g.2m. Снятие последней
отметки сохраняет пустой выбор. Один документ может выбрать до восьми моделей.
Модели, уже выбранные для открытой сцены, видны в списке до регистрации в каталоге.

Переключение флажков обновляет набор ресурсов для Build. Размещённые объекты
создаются через authoring-команды. Перед сборкой Editor проверяет исходники
и наличие ресурсов, на которые ссылаются размещённые модели.

[Воспроизводимый профиль](../../ManualTests/ModelBuildConsumer/README.md#select-project-models-in-editor).

## Первичный импорт из Editor

После `UseNom()` и `UseAetherNomContent()` зарегистрируйте
`UseAetherNomProjectModelImports(worker, scratchDirectory)` перед
`UseAetherProjectModelCatalog()` и Editor. Доверенный worker и рабочий
каталог задаёт приложение. В примере их можно передать через CLI.
[Запуск примера](../../Examples/AetherEditor/README.md).

В меню «Проект» выберите «Импортировать модель» и укажите путь к
`.gltf` или `.glb` относительно корня проекта. Capture читает модель
и её зависимости. Editor публикует ledger и точные ресурсы в Nom, затем
атомарно добавляет строку каталога. Для размещения отметьте модель в
«Модели проекта» и нажмите «Добавить в сцену».

В каталоге контента проекта сохраняются `.aether-model-ledgers`,
`.aether-model-content` и запись `.aether-model-catalog.json`. При сбое
регистрации по прежнему пути повторно используется ledger с той же ревизией
входа. Повтор уже зарегистрированного пути оставляет единственную запись.
Для замены содержимого зарегистрированной модели служит переимпорт.
[Воспроизводимый профиль](../../ManualTests/ModelBuildConsumer/README.md#import-the-first-model-from-editor).

<a id="arch1g2o-place-catalog-model"></a>
## ARCH1g.2o — размещение модели из каталога

Отметьте модель в каталоге ресурсов открытой сцены, затем нажмите «Добавить
в сцену» в её строке. Editor использует закреплённое поколение, сохраняет ID
экземпляров и мешей и размещает экземпляры в импортированных мировых позах.
Один импорт можно разместить один раз в сцене.

Один Undo убирает добавленные экземпляры и их новые определения и схемы.
Выбор импорта сохраняется, поэтому Redo восстанавливает те же экземпляры.
Команда «Сохранить сцену» записывает размещение в документ. При открытии Editor
восстанавливает размещение из документа, а выбор ресурсов из записи ARCH1g.2m.
[Приёмка](../../ManualTests/ModelBuildConsumer/README.md#place-a-catalog-model-in-the-scene).
