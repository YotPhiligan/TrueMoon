# UI TrueMoon на Argentis и Alloy

Собирай View так, чтобы по Fluent-дереву читались порядок блоков, видимые
состояния, привязки и действия пользователя.

## Источники

- Начинай с [AGENTS.md](../../../src/AGENTS.md) в каталоге `src` и текущего
  [статуса Alloy](../../../src/docs/alloy/STATUS.md).
- Для визуальных решений используй [дизайн-код](../../../src/docs/alloy/DESIGN.md).
  Для выбора проверки используй [UI_TESTING](../../../src/docs/alloy/UI_TESTING.md).
- При композиции, миграции или генерации частей открывай
  [пример обозревателя](references/editor-hierarchy.md). Сверяй спорный API
  с исходниками и [контрактом UIA1f.11](../../../src/docs/alloy/PLAN.md#uia1f11-contextual-content).
- Импортируй `TrueMoon.Argentis.Views` для `View` и `ui.*`, `Styling` для
  `IViewStyle` и его правил, `Input` для команд и `IInputContext`; это
  подпространства `TrueMoon.Argentis`, а не новые пакеты. Корень нужен для
  `UiProperties` и сгенерированных Fluent-расширений контролов. Остальные типы
  ищи по [карте UIA1i](../../../src/docs/alloy/PLAN.md#uia1i-argentis-structure).

## Проектирование и реализация

1. Определи основной сценарий и действия с клавиатуры. Учти пустое состояние,
   ошибки, недоступные действия и узкий viewport, когда они влияют на экран.
   Расположи блоки в порядке чтения и взаимодействия. Подписывай действия и
   задавай `AccessibleName` там, где видимого текста недостаточно.
2. Объявляй дерево в конструкторе через `Content(data, ui => ...)` или
   `Content(ui => ...)` для View без модели. Создавай контролы через
   `ui.Create<TControl>()` и шорткаты `ui.Text(...)`, `ui.Button(...)`,
   `ui.HStack(...)` и `ui.VStack(...)`. `Fill()` отдаёт элементу долю
   остатка по оси стека. Описывай дерево и обработчики в одном файле.
   Действия в одну-две строки оставляй в дереве, более длинные размещай
   ниже. Возвращай корень, созданный этим `ui`, и включай в него каждый
   контрол, полученный из контекста. Для готового поддерева используй `SetContent`.
3. Держи draft, доступность команд и ошибки в Data/ViewModel, а фокус,
   прокрутку и жизненный цикл контролов — во View. Для чтения используй
   `Bind`, для редактирования — `BindTwoWay` или точечный сгенерированный
   метод вроде `BindValueTwoWay(data => data.SearchText)`. В цепочке
   `UiControl<TControl, TData>` селектор следует за текущим `IDataContext<TData>`.
   Для другого источника передай его явно.
   Для готовой команды текущей модели используй `WithCommand(data => data.FindCommand)`,
   для общей стабильной команды — `WithCommand(command)`. Кнопка и клавиатура
   выполняют одну команду.
4. Оформляй экран в `IViewStyle<TView>`. Выбирай `Root`, `Part`,
   `TypedPart` и `Role` по цели правила. Для динамических элементов
   используй семантическую роль. Цвет, шрифт и размеры бери из Theme там,
   где они общие. Приоритет значений сохраняй в порядке
   local/binding → Style элемента → стиль View → Theme → default.
5. Именуй только части, к которым обращаются поведение, стиль или проверка.
   Генератор находит прямые вызовы `Named("Имя")` в inline-фабрике
   `Content(...)` и выпускает свойства-расширения типа самого контрола.
   Части доступны с `OnContentPrepared()`, когда дерево уже принято, а
   attach-уведомления и первый layout ещё впереди. Вложенное View хранит
   имена в собственной области. Если генератор не подключён, используй
   `GetRequiredPart<T>()` или `TryGetPart<T>()` после подготовки дерева.

Для новых Fluent-методов следуй схеме `Property(value)`, `On<Event>(handler)`
и `With<X>(...)`. Сеттер вызывает штатный путь установки, `On` подключает
обработчик события, а `With` объявляет композицию или связь. Владение и
время жизни определяются контрактом операции. Планируемые методы помечай
как предложения, готовые примеры составляй из доступного API.

## Владение и проверка

- Фабрика создаёт View на UI owner thread и вызывает `ViewCreation.Prepare(view, style)`.
  Сессия выполняет фабрику из `Content(...)` при первом attach и применяет
  стиль после `OnContentPrepared()`. При reattach готовые контролы
  сохраняются. Деревом владеет окно или родитель, а модель и стиль
  заимствуются. Для своего контрола зарегистрируй `IFactory<TControl>`
  или `IFactory<TControl, TArguments>` в реестре сессии.
- Наблюдай текущую модель на срок attachment через
  `.ObservePropertyChanged(handler, synchronize)` в цепочке контрола или
  `this.ObservePropertyChanged(this, handler, synchronize)` на View.
  Обработчик уведомлений идёт через очередь UI. `synchronize` читает
  состояние при attach и смене контекста. Подписку с ручным снятием
  привязывай к тому же экземпляру контрола.
- Проверяй затронутое поведение через `UiSession` и маршрутизируемый ввод.
  При смене темы проверяй сохранение фокуса, прокрутки и черновика там,
  где они есть. При изменениях подписок проверяй detach, reattach и
  `Dispose`. Добавляй CPU raster для визуальных изменений и native профиль
  для сценариев, зависящих от окна или GPU.
